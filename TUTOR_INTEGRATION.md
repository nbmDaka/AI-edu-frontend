# ИИ-тьютор на странице лекции

Панель подключена на страницах `/lessons/:id` и `/items/:id` для типа `LECTURE`. Вопросы идут через Django по `/api/v1/tutor/chat/`. Настройка AI-сервиса и его ключа описана в `TUTOR_INTEGRATION.md` репозитория backend.

Панель показывает потоковый ответ и фрагменты материала, поддерживает отмену ответа, копирование и очистку диалога. История хранится в sessionStorage отдельно для пользователя и лекции. При смене лекции активный запрос отменяется, а на новой странице открывается её собственный диалог. На узких экранах тьютор открывается кнопкой в верхней панели.

Для локального Vite задайте `API_PROXY_TARGET=http://127.0.0.1:8010` и добавьте origin frontend в `CSRF_TRUSTED_ORIGINS` Django. Для собранного frontend также можно задать `API_PROXY_TARGET` при запуске `node server.mjs`; сервер поддерживает потоковый proxy. Без этой настройки production сохраняет схему с внешним reverse proxy.

```bash
npm ci
npm run build
npm test
API_PROXY_TARGET=http://127.0.0.1:8010 PORT=5173 node server.mjs
```

Используйте Node.js 24, как в Dockerfile. Ключ OpenAI и сервисный ключ AI не нужны frontend и не должны попадать в его bundle.

## Голос

Кнопка микрофона записывает вопрос до 60 секунд; повторное нажатие завершает запись. Распознанный текст появляется в поле вопроса, чтобы студент мог проверить его перед отправкой. Переключатель с динамиком включает автоматическую озвучку; рядом с ответами доступно ручное воспроизведение и остановка. Озвучка сейчас только на русском, распознавание также принимает казахский и английский.

При смене лекции прекращаются запись, воспроизведение и незавершённые запросы. Микрофон работает на localhost или HTTPS и требует разрешения пользователя. В обычной сборке доступны запись отдельного вопроса, потоковый текстовый ответ и его озвучка.

## Локальный прототип аватара

Исходники локального viewer, SSE-шлюза и NVIDIA-worker находятся в backend-репозитории: `services/avatar-local`. Запуск описан в его README.

`VITE_LOCAL_AVATAR=1` при сборке включает интеграцию с отдельным локальным viewer на порту 5184. Флаг дополнительно проверяет hostname: на внешнем домене аватар не появляется даже с этим флагом. Backend также разрешает маршрут аватара только в `DEBUG=true` и с loopback-адресом сервиса. Не включайте DEBUG на рабочем сервере ради аватара.

Для этого режима нужны отдельно запущенные OpenAI-шлюз аватара, NVIDIA Audio2Face и viewer. Браузер получает PCM и лицевые веса по SSE через авторизованный Django API; iframe получает их через postMessage с проверкой origin и отправителя. Озвучка и лицевые веса используют общий таймер воспроизведения. Смена лекции, остановка ответа и закрытие панели отменяют запрос и воспроизведение.

В режиме локального аватара кнопка телефона включает непрерывный разговор на русском: после паузы 900 мс вопрос распознаётся и отправляется автоматически. Обнаруженная речь прерывает ответ. При смене лекции, скрытии вкладки и завершении разговора микрофон освобождается. Голосовой детектор и WASM загружаются с `/voice-assets/`, а не с внешнего CDN; Vite копирует нужные файлы зависимостей при сборке. Наушники рекомендуются, работа с физическим микрофоном и колонками требует отдельной проверки.

Это прототип с фразовой генерацией речи, не OpenAI Realtime speech-to-speech. В текущем viewer жесты руками отключены после проверки пользователем; приветствие заменено небольшим кивком. Пробная модель Кевина, NVIDIA runtime, веса, ключи и аудиозаписи в GitHub не входят. Обычная сборка и автоматический деплой не запускают аватар.
