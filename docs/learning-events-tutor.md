# Второй этап adaptive support

Рекомендации первого этапа сохранены без изменения правила. Основная реализация журнала и AI-контекста находится в Django backend; контракт и ограничения — `AI-edu-backend/docs/learning-events-tutor.md`.

`TestRunner.tsx` передаёт UUID `request_id` при сдаче теста. Один ключ используется при потерянном ответе и повторе после перезагрузки, новый — после успешной сдачи или изменения ответов. Ключ хранится в sessionStorage рядом с черновиком текущего пользователя, материала и версии теста; при недоступном хранилище остаётся в памяти экрана. Старые API-клиенты без ключа совместимы, но для них повтор POST является новой попыткой.

Новых экранов/надписей этот этап не добавляет. Журнал доступен владельцу через `GET /api/v1/learning-events/` и администраторам через тот же API/Django-admin. Тьютор получает учебные результаты на сервере после проверки материала: браузер не собирает и не отправляет авторитетный контекст.

Проверки: `npm test`, `npm run build`, сценарий `e2e/adaptive.integration.e2e.ts` с реальным локальным Django на временной SQLite. Сценарий проверяет оба этапа, включая replay запросов и журнал; ru/en/kz, 1280/390. Контракт prompt проверяется детерминированно на backend без внешнего AI. Никаких commit/push/deploy не выполнялось.
