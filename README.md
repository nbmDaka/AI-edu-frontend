# AI Edu frontend

Раздел администратора `/admin/analytics`: статистика студентов, траекторий, курсов
и модулей из `GET /api/v1/admin/analytics/`. Есть фильтры периода/траектории/курса
в URL, поиск, сортировка, страницы, экспорт CSV и адаптивная вёрстка. Период
ограничивает активность; начало и завершение показываются за всё время. Общее
число студентов относится ко всей платформе. Обновлять вместе с backend;
миграции не нужны. Проверки: `npm test -- src/admin/AnalyticsPage.test.tsx
src/admin/AdminWorkspace.test.tsx`, `npx playwright test e2e/analytics.e2e.ts`.

Оформление старой платформы поверх новой функциональности: [описание и проверка](docs/legacy-theme.md).

Админский редактор лекций (`src/LessonEditorPage.tsx`, `src/lecture/`) использует единый Tiptap-документ:
общее выделение и история отмены, белый лист и постоянная панель «Главная / Вставка» с обычными
инструментами форматирования. Таблицы, изображения, врезки, разделители, LaTeX и видео по HTTPS-ссылке
(YouTube, RuTube, MP4). Формулы редактируются нажатием; подпись, альтернативный текст, ширина
и замена изображения доступны при его выборе. Оглавление открывается по кнопке; ручки перетаскивания
включаются через «Дополнительные инструменты → Упорядочить элементы». Дополнительно поддерживается `/`.
Материалы для скачивания свёрнуты под документом, черновик можно сохранить через Ctrl+S / Cmd+S.
AI в этом редакторе не используется.

Формат API не изменён: текстовые фрагменты сохраняются в `TEXT`, изображения — в `IMAGE` с отдельными
ссылками на медиа для существующей проверки доступа. Старые лекции открываются без миграции.
Черновик сохраняется автоматически; студентам изменения доступны после публикации.

Браузерные проверки редактора используют подменённый API и не обращаются к рабочему backend:
`npx playwright install chromium`, затем `npm run test:editor`. Они запускают отдельный Vite на порту 5178.

`lecture_workshop@1.0.0` поддерживает двухпанельную мастерскую на `/items/:id`: параметры лекции,
AI-чат, улучшение запроса, генерацию, редактор Tiptap и сдачу с самооценкой.
[Описание интерфейса, API и ограничений восстановления](docs/lecture-workshop.md).

Практические работы используют Practice Engine: каталог карточек из `GET /api/v1/practice-types/`, динамический редактор конфигурации и student runtime. Реализован `checklist_practice@1.0.0`. Компоненты и контракт находятся в `src/practice/`; регистрация нового типа — в `registry.ts`. Backend должен зарегистрировать manifest с тем же кодом и версией. Неизвестные типы отображаются недоступными.

Редактор сохраняет черновик отдельно от публикации. Начало student attempt закрепляет версию задания; frontend отправляет только ID попытки и состояния критериев. Значение Ψ, источник и прогресс возвращает сервер. Архитектура, API и миграции описаны в README backend, разделе Practice Engine. Проверки: `npm test` и `npm run build`.

React + TypeScript интерфейс для платформы. Репозиторий содержит отдельный Compose-проект только для frontend-сервиса.

## Docker Compose

Сначала запустите backend из его репозитория. Он создаёт общую Docker-сеть `aiedu-platform` и сервис `backend`. Затем:

1. Скопируйте `.env.example` в `.env`. По умолчанию frontend обращается к backend по внутреннему адресу `http://backend:8000`.
2. Запустите из корня этого репозитория:

```bash
docker compose up --build -d
```

Приложение откроется на `http://localhost:5173`. Этот Compose содержит только сервис `frontend`; PostgreSQL, Redis, MinIO и Django запускаются из репозитория backend. Во frontend `.env` нет паролей или ключей.

## Production

После запуска backend с его `docker-compose.prod.yml` выполните:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d
```

Production frontend собирается и раздаётся Node-сервером на порту 3000 контейнера, доступном на хосте как `127.0.0.1:8080`. Внешний Nginx обслуживает `https://aiedu.com.kz`: `/api/` направляет на backend `127.0.0.1:4000`, остальные запросы — на frontend `127.0.0.1:8080`. Сохраните существующий маршрут Django static files. Пример маршрутов и значения backend `.env` приведены в README backend.

Браузер использует относительный адрес `/api/v1/`, поэтому домен API в frontend `.env` для production задавать не нужно. `API_PROXY_TARGET=http://backend:8000` в `.env.example` предназначен для Docker-разработки; standalone production Compose передаёт API внешнему Nginx и не загружает этот `.env` в Node-процесс.

## Локальная разработка без Docker

```bash
npm ci
npm run dev
```

Vite использует `API_PROXY_TARGET` из `.env`: в Docker — `http://backend:8000`, вне Docker — `http://localhost:8000`. Без этой переменной Vite обращается к `https://aiedu.com.kz`.

Проверки: `npm run test`, `npm run build`.

В редакторе лекции доступна кнопка **«Импорт из файла»** для PDF, DOCX и PPTX. Backend автоматически выбирает нативное извлечение, OCR для изображений и сканов, затем уточнение неоднозначной структуры через ИИ. В окне отображается только результат. Для переноса обязательно нажмите одну из кнопок **«Добавить в конец»** или **«Заменить содержимое»**; до выбора «Перенести в черновик» недоступно. Вставка сохраняет историю отмены редактора. Закрытое окно можно открыть снова: задания продолжают обрабатываться. Для работы нужен `import-worker`; установка OCR, параметры и ограничения описаны в разделе «Импорт лекции из файла» README backend. На frontend отдельные AI-ключи не нужны. Проверка интерфейса: `npm run test:editor`.

На вкладке **«Главная»** доступны цвет текста и выделение фоном: готовые оттенки, произвольный цвет и сброс. Маркированные и нумерованные списки отображаются в редакторе, импорте, предпросмотре и опубликованной лекции; `Enter` добавляет пункт, `Tab` / `Shift+Tab` меняют вложенность. При импорте сохраняются цвета фрагментов Word/PowerPoint, вложенность и начальные номера списков. Из PDF с текстовым слоем переносятся цвета совпавших исходных символов и аннотации выделения; восстановление цветов из сканов через OCR не гарантируется.
### Student learning links

The student flow uses `/items/:id`. Existing `/lessons/:id` bookmarks resolve the
explicit `learning_item_short_id` relation returned by the lesson API and redirect
with history replacement. Migrated lectures keep their original public ID, but
the relation is used rather than assuming the IDs always match. If a legacy
lesson has no LearningItem relation, the page explains that it is unavailable
and offers the catalog; it does not run a second learning/progress flow.

`GET /api/v1/me/learning/` supplies the dashboard in one request. Course progress
uses the same server derivation for completion and resume. Scroll percentages
are preserved; exact scroll restoration is intentionally left for a later step.

Содержание курса можно закрыть и открыть из шапки. Модули сворачиваются отдельно или все сразу; состояния материалов показаны иконками с доступными подписями. Выбор скрытой боковой панели сохраняется в текущей вкладке. Содержание доступно и в практике с редактором документа, а тьютор отображается только у лекций. Для продолжения есть одна кнопка «Перейти к следующему материалу»; другие материалы выбираются в содержании.

У теста сначала отображается описание и условия. «Начать тестирование» открывает отдельный экран (`?view=assessment`) без боковых панелей. Выбранные ответы сохраняются в `sessionStorage` по пользователю, материалу и версии теста; выход или перезагрузка не расходуют попытку. Отправка требует ответить на все вопросы и подтвердить завершение в диалоге. После отправки показываются оценка, разбор каждого вопроса и переход дальше; результаты доступны повторно из истории (`?view=results&attempt={id}`). Ограничения попыток и блокировки модулей проверяются backend. Существующие результаты без полного снимка вариантов отображаются в прежнем текстовом формате.

### Адаптивное обучение и «Мой прогресс»

После теста показаны сохранённые сервером готовность, порог, показатели и компетенции в порядке возрастания значений. У отдельных компетенций нет проходного порога: следующий модуль открывается по общей готовности. Формула и правила backend не меняются. При провале незавершённого модуля сервер сбрасывает прогресс опубликованных лекций и актуальность практических сдач; после повторного изучения и сдачи практики тест можно пройти снова. Старый неудачный результат не блокирует новую попытку на клиенте, лимит и обязательное повторение проверяет сервер.

В результате неудачной попытки доступны текущие опубликованные и незаблокированные лекции и практики этого модуля в порядке курса. Подбор по отдельной компетенции не выполняется: такой связи в API нет. Если модуль или его материалы больше недоступны, ссылки не показываются. Отсутствующие компетенции и `adaptive_result` не заменяются искусственными значениями.

Страница `/#/progress` доступна из меню «Мой прогресс»: курсы без дубликатов, завершённые материалы и история тестов с загрузкой следующих страниц. Ошибки прогресса и истории независимы. Детали исторических попыток используют сохранённые тогда показатели, а материалы для повторения загружаются заново. Внутри теста история также имеет страницы; ссылка на старую попытку сохраняет `history_page`, чтобы пережить перезагрузку. После лекций, практик и тестов обновляется кэш прогресса, сводки, траектории и материалов. Интерфейс поддерживает ru/en/kz и узкое меню в две колонки.

### Проверка с реальным локальным backend

`e2e/adaptive.integration.e2e.ts` не подменяет API. Сценарий проходит лекцию и практику через интерфейс, достигает проходного процента теста без готовности модуля, проверяет сброс прогресса и отказ сервера без повторения, повторяет материалы, достигает готовности без проходного процента теста и проверяет открытие следующего модуля. Поздняя неудача сохраняет доступ; также проверяются история и мобильное меню. Проверяются 1280/390 px и переводы ru/en/kz. Без `AI_EDU_INTEGRATION_FIXTURE` сценарий пропускается.

Для воспроизведения нужен установленный Chrome и Python-окружение основного Django backend. В PowerShell из каталога backend запустите:

```powershell
$env:PYTHONPATH = (Get-Location).Path
python ../AI-edu-frontend/e2e/fixtures/adaptive_backend.py
```

Скрипт создаёт новую SQLite-БД в отдельном временном каталоге, применяет миграции, добавляет тестовые данные и запускает Django на `127.0.0.1:8017`. Он переопределяет БД, хранилище файлов, почту и кэш до запуска Django; основная БД и файлы backend не изменяются. Скопируйте напечатанный JSON после `AI_EDU_INTEGRATION_FIXTURE=`. В другом PowerShell из frontend:

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8017'
$env:AI_EDU_INTEGRATION_FIXTURE = '<JSON из вывода скрипта>'
npm run test:editor -- adaptive.integration.e2e.ts
```

Playwright сам запускает frontend на `127.0.0.1:5178`. После проверки остановите Django (`Ctrl+C`); путь к временной БД напечатан скриптом. Для повторного запуска сценария запустите скрипт заново, чтобы получить чистые данные. Скриншоты находятся в `test-results/adaptive-*.png`.

Адаптивные попытки отдельно показывают результат теста (`passed`, процент баллов) и результат модуля (`module_passed`, готовность и порог сервера). Завершение модуля (`module_completed`) сохраняется после поздней неудачной попытки. Процент теста не определяет допуск. История в тесте и «Моём прогрессе» показывает состояние на момент попытки; текущую доступность проверяйте в курсе. Ссылка перехода из свежего результата использует решение сервера. Обычные тесты сохраняют прежние правила. Реальный интеграционный сценарий проверяет оба направления расхождения за счёт разных весов вопросов и сохранение завершения после неудачи.
